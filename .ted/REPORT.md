Resources remains inside Me. Shared invitation links retain the code through sign-in and require a deliberate join. Expired sessions preserve the intended page and non-sensitive form draft without automatically submitting a mutation. Session tokens remain only in memory, so reopening the app requires signing in again. Guest book browsing and local preferences remain available without an account. A failed directory read is explicitly unavailable, rather than presented as a real count of zero.

Email codes go through the Bookish-specific auth function and Bookish's Resend sender. The source does not change the shared Supabase Auth templates or provider settings. An optional password path supports existing Bookish accounts and reviewer credentials. There is no social sign-in provider in this release. New identities receive trusted app_metadata.app=bookish from the server; user-editable metadata is not trusted. Existing unmarked identities, including Fictora identities, are neither promoted nor deleted. This intentionally means an email already belonging to an unmarked Fictora identity cannot create a second Bookish identity in this shared Auth project. That reader needs a separate Bookish email or a later identity architecture decision. Generic public auth responses avoid exposing identity membership.
